## §06 detail — the one ⚠️ (KNOWN family, second instance; NOT a new engine bug)

Asked CC to build+run `REG-headcount-file` (Database → Set Variable → File). All 3 steps reported
Completed and CC said "file successfully written" — but the file was **0 bytes**. Diagnosis from the
persisted config + run variables:

- Database node: **correct** (`headcount_rows` = envelope with all 10 rows).
- CC-native authored the Set Variable node with **wrong config keys** — `useExpression`/`value`
  instead of the engine's `evaluateAsExpression`/`valueExpression` (plus a Python expression over the
  envelope as if rows were dicts). The engine silently resolved the variable to `""`.
- File node dutifully "successfully" wrote the empty string.

This is the **same root cause as the known CC-native Excel defect** (prompt catalog names no config
fields; no save-time key validation) — a second concrete instance (Set Variable now, Excel before),
plus the same silent-success-over-empty-content class. Engine primitives are proven green by pack 14
(`setvar_file_write` writes real content when configured correctly). **Extend the eventual fix task
to cover Set Variable, and consider a Set Variable rule in the pack-14 lint.**
